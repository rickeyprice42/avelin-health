# Разработка Avelin Health

## Решение от 10 октября 2026 года

Приоритет — веб-MVP, готовый к ограниченному тестированию на компьютере и iPhone Safari. Backend и БД планируются на VPS Ubuntu. Desktop/Tauri и нативное iOS-приложение отложены. Текущий Python-сервер и SQLite — локальная основа прототипа; серверную архитектуру ещё нужно определить.

## Рабочий процесс

Linear хранит задачи, требования и критерии приёмки. GitHub хранит исходники, историю изменений и результаты проверок.

1. Выбрать задачу Linear и определить проверяемый результат.
2. Создать ветку вида `ave-8-health-import`.
3. Внести изменение и выполнить подходящие проверки из README.
4. Открыть pull request со ссылкой на задачу, описанием результата и проверок.
5. Слить после проверки; обновить статус Linear по фактической готовности.

Используйте `pnpm install --frozen-lockfile` и сохраняйте lockfile вместе с изменениями зависимостей. Личные данные не используйте в тестовых фикстурах, issue, PR или CI-артефактах.

## Перед первым внешним тестированием

- Согласовать веб-архитектуру и модель доступа: AVE-5, AVE-6, AVE-7.
- Реализовать аутентификацию, изоляцию данных и управление согласием: AVE-11, AVE-20, AVE-21.
- Добавить безопасный импорт через сайт, ограничения размера и обработку ошибок: AVE-8.
- Проверить временные зоны, единицы и пересечения источников: AVE-10, AVE-22.
- Синхронизировать цели питания и полный профиль с инструментами агента: AVE-16, AVE-17, AVE-19.
- Завершить каталог, рецепты и сохраняемые списки покупок: AVE-25–AVE-31.
- Подготовить HTTPS, резервное копирование, восстановление и выпуск на VPS: AVE-6, AVE-11, AVE-24.
- Проверить сквозные сценарии и ошибки на desktop и iPhone Safari: AVE-13, AVE-23, AVE-31.

## Что нельзя добавлять в Git

Экспорты Apple Health, SQLite, сводки с личными измерениями, реальные выгрузки каталогов с заметками, HAR, профили браузеров, ключи и личные переписки. Эти классы файлов исключены через `.gitignore`.

Перед коммитом проверяйте `git status --short` и `git diff --cached`. Правила ignore не удаляют уже опубликованные данные из истории. Синтетические примеры при необходимости добавляйте в отдельную папку фикстур с точечными исключениями.
