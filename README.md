# Avelin Health

Персональное веб-приложение для анализа данных Apple Health, диалога с ИИ и планирования питания на основе каталогов магазинов.

**Статус: прототип, подготовка веб-MVP к тестированию.** Целевая платформа — адаптивный сайт для desktop-браузера и iPhone Safari, backend и БД на VPS (предварительно Ubuntu). Отдельное desktop-приложение, Tauri и нативный iOS-клиент отложены.

[План работ в Linear](https://linear.app/avelin-health/project/avelin-health-517c7a274971)

## Что реализовано

- React + TypeScript + Vite: сводка, тренды, питание, профиль, каталог, чат и качество данных.
- Python + SQLite: потоковый XML-импорт Apple Health, дедупликация записей, дневные агрегаты и приоритеты источников.
- Импорт каталога CSV и прототипы сборщиков в `kuper_catalog_prototype/`.
- Локальные ответы чата и интеграция облачной модели с ограниченным набором инструментов.
- Тесты инструментов агента и парсеров.

## Ограничения текущей версии

Backend предназначен для локальной разработки и слушает `127.0.0.1`. Аутентификация, безопасная загрузка ZIP через сайт, резервное копирование и конфигурация VPS ещё не реализованы. Не публикуйте текущий сервер в интернете с личными данными.

Цели питания пока сохраняются в браузере и не синхронизируются с БД агента. Инструмент профиля пока не возвращает аллергии и предпочтения. Каталог не содержит подтверждённых КБЖУ после текущего импорта. Рецепты, интерактивные карточки в чате и сохраняемые списки покупок — следующие этапы. Часть кнопок интерфейса пока является заготовками.

## Запуск с рабочего стола (Windows)

Один раз выполни в корне проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/install_launcher.ps1
```

На рабочем столе появится **Avelin Health - Local**. Двойной щелчок запускает Python API и Vite, ждёт их готовности и открывает http://127.0.0.1:4173. Окно управления позволяет открыть сайт повторно, посмотреть логи и остановить серверы. Закрытие окна также останавливает процессы, запущенные этим окном. Повторный щелчок по ярлыку не создаёт вторую пару серверов.

Изменения frontend подхватываются автоматически. После изменения Python backend нажми «Остановить», затем «Запустить». Если серверы уже запущены отдельно и распознаны как Avelin, окно использует их и не останавливает при закрытии. При конфликте портов запуск завершается с объяснением; чужие процессы не завершаются.

Логи: `.local/logs/backend.log` и `.local/logs/frontend.log`. Пути к Python и Node сохраняются в `.local/launcher.json`. Эти файлы исключены из Git. При перемещении проекта или обновлении путей к среде выполни установщик повторно (старый ярлык при конфликте переименуй).

Нужны уже установленные зависимости и импортированные Health/каталог по инструкции ниже. Ярлык не читает файлы с API-ключами и не загружает `.env`. Чат без ключа работает в локальном режиме; состояние показано в окне. Для облачного режима переменные окружения должны быть заданы до запуска.

Проверка запуска без окна и браузера: `python scripts/launch_local.py --check`. Она проверяет доступность обоих HTTP-сервисов и останавливает только запущенные ею процессы.

## Локальный запуск

Все команды выполняются из корня репозитория. Личные данные не входят в Git.

```powershell
pnpm install --frozen-lockfile
python scripts/import_apple_health.py apple_health_export/export.xml
python scripts/import_product_catalog.py "Каталоги магазинов/Все магазины.csv"
```

Первый скрипт создаёт SQLite и сводку, затем пересчитывает дневные агрегаты. Второму нужен CSV из прототипа каталога; он создаёт таблицу товаров. Для профиля, каталога и чата подготовьте оба источника. При отсутствии данных можно открыть оболочку frontend, но это не полный сценарий тестирования.

Два терминала:

```powershell
# Терминал 1: API, http://127.0.0.1:8765
pnpm server
```

```powershell
# Терминал 2: интерфейс, http://127.0.0.1:4173
pnpm dev
```

Проверка сборки: `pnpm build`. После сборки `pnpm server` также раздаёт интерфейс из `dist/` на порту 8765. `pnpm preview` служит только для просмотра frontend и не заменяет API-сервер.

## Настройка ИИ

Без `OPENAI_API_KEY` чат использует локальные диагностические ответы. Для облачной модели задайте `OPENAI_API_KEY` и `AVELIN_OPENAI_MODEL` в окружении процесса backend перед запуском `pnpm server`. Модель должна быть доступна вашему API-проекту и поддерживать используемые инструменты.

Сервер не загружает `.env` автоматически. Не вставляйте ключи в исходники, frontend, коммиты, задачи или логи. При включении облачного режима сообщения и результаты вызванных инструментов передаются провайдеру модели; это не полностью локальная обработка.

## Проверки

```powershell
python -m pip install -r requirements-test.txt
python -m unittest discover -s scripts -p "test_*.py" -v
python kuper_catalog_prototype/test_parser.py
node kuper_catalog_prototype/test_nutrition_parser.js
pnpm build
```

GitHub Actions запускает сборку и эти тесты при push и pull request. Тесты используют синтетические данные и временные файлы; доступ к личному экспорту и API-ключу им не нужен. Это базовые проверки, не подтверждение готовности всего MVP.

## Структура

- `src/` — интерфейс и логотип.
- `scripts/` — импорт, агрегация, локальный API и инструменты агента.
- `kuper_catalog_prototype/` — сборщики и обработка каталогов.
- `docs/` — архитектура и процесс разработки.
- `.github/workflows/` — автоматические проверки.
- `data/`, `public/data/`, `apple_health_export/` — локальные данные, исключённые из Git.

## Принципы

Сохраняем происхождение измерений, явно показываем пропуски и неопределённость, отделяем подтверждённые КБЖУ от оценок. Ответы не заменяют медицинскую диагностику. Доступ к серверным данным и передача модели должны управляться пользователем.
